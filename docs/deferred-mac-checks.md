# Deferred checks for masked SPDZ openings

This design queues authentication checks for internal Beaver and square-mask openings. It does not defer the check past the transmission of unmasked output shares. It assumes correct fresh authenticated preprocessing, at least one honest party, confidential authenticated channels, consistent broadcasts with abort, and one ordered protocol stream per key set.

This ordering is standard in SPDZ. [Turbospeedz, Figure 2](https://eprint.iacr.org/2019/080) checks all previous online openings before opening the final output, then checks the output itself. The local MP-SPDZ `Protocols/Beaver.hpp` similarly consumes raw masked openings, while `Protocols/MAC_Check.hpp` accumulates their values and MACs until `Check()` or a batch threshold. Its optional `always_check` setting forces immediate checks.

## Allowed operations and output boundary

Only the protocol implementation may queue a masked opening. The allowed values are `X-A` and `Y-B` for a freshly consumed matrix/elementwise triple, or `X-A` for a freshly consumed square mask. A generic caller must not label an arbitrary secret as masked. Each mask is independent of all previous online openings and unknown to the corrupt coalition. Correlation identifiers, dimensions, and consumption checks remain immediate.

For each opening, parties immediately complete the value broadcast and its consistency echo. They retain an immutable authentication snapshot and its ordered session/operation/layout binding: either the exact candidate values and original local MAC shares, or the residuals computed from those values immediately after the broadcast. These candidates may enter tentative local authenticated arithmetic and later masked openings. They must not control an input-dependent branch, memory address, error message, log, public return value, or external side effect. The intended first implementation is a fixed public matrix/square circuit.

Before broadcasting any unmasked final output share, each party checks every queued opening together. A successful check empties the queue. A failed or interrupted check poisons the session, closes its transport, and permanently retires its keys and all remaining correlations. Recreating a party with those keys is forbidden. After a successful flush, parties open the final output using its ordinary checked opening. They return it only after its own MAC check succeeds. The final-output API must enforce this order automatically; a caller-managed optional flush is insufficient.

## Why masked continuation is permitted

Given the corrupt view and previous transcript, a fresh preprocessing mask makes the next honest masked value uniform. The adversary may alter a candidate opening, and tentative arithmetic may consequently contain an error depending on secrets. The next internal value is still hidden by a new independent mask. This argument depends on the preprocessing protocol's conditional privacy guarantee, not merely on each mask having a marginally uniform distribution.

Authentication checks bind the exact candidate values already fixed by the completed broadcasts. Fresh independent per-key compression challenges are generated only after the queued candidates are fixed, and all compressed residuals are committed before any honest residual is revealed. The existing compressed-check assumptions and soundness terms therefore apply to the combined batch. Honest arithmetic is correct if all candidate openings are authentic. Any failure releases no unmasked result, and retires the authentication state. This is the usual masked-evaluation/checked-output argument; it is not a new proof of preprocessing or the complete implementation.

Deferring through the final output broadcast is unsafe even if the application waits to return the result. For a multiplication whose legitimate output is `0*y = 0`, changing the opened first Beaver difference by `+1` changes the tentative result to `y`. Sending those output shares exposes `y` before the later check can abort. Neither rejecting the result afterwards nor throwing an exception removes that information. `tests/test_deferred_mac_design.py` checks this algebraic counterexample and the independent-mask property over a small field.

## Round and storage costs

With consistent broadcast implemented as value plus echo, each queued masked opening costs two exchanges. One combined compressed check costs eight exchanges: coin commitment, coin reveal, residual commitment, and residual reveal, each with an echo. A compressed final checked opening costs ten exchanges. A full-vector final check needs six exchanges and retains every MAC coordinate; it needs no compression coin.

For three internal openings followed by one compressed final opening, this gives `3*2 + 8 + 10 = 24` exchanges, compared with `4*10 = 40` for immediate compressed checks. The implemented deferred backend instead selects a full-vector check for final outputs of at most 4096 field values by default, reducing this count to `3*2 + 8 + 6 = 20`. Its public `output_check_threshold` and selected mode are bound into protocol contexts; setting the threshold to zero forces compression. The device square path binds its mask identifier in the masked-opening label, so it needs no separate agreement broadcast. Include any owner-input correction and setup broadcasts when reporting whole-program totals.

The queue retains all pending authentication snapshots until the flush. Storing immediate residual copies avoids retaining both MAC vectors and candidate values. Those tensors must not alias mutable scratch buffers or recycled preprocessing storage. Large circuits need a public queue-size limit and intermediate flushes to bound memory. These extra flushes preserve the output boundary and change the measured round count. The first implementation must retain the immediate-check path as a comparison oracle and test injected errors in every queued phase, peer failures during flush, and rejection before the first final-output frame is transmitted.
